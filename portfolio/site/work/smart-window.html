Smart Window / AI Mode

Director, Mobile & AI UX 2026 Nova program gates

Stakes

Every browser is adding AI. The risk isn't being late. It's stapling a chatbot to chrome and calling it innovation. Smart Window has to feel opt-in, trustworthy, and distinctly Firefox.

Classic Mode is still Firefox. AI Mode is for when you want the browser to carry more of the task, with consent.

The call

  • Three modes, one product. Private (on-device). Classic (familiar Firefox). AI Mode (context-aware assistant on Mozilla's terms).
  • Design the states nobody sees. Loading, error, empty, reduced-motion, the moment after the user turns AI off. Same intentionality as hero moments.
  • Greenfield token discipline. 100% font-size tokenization on AI Window surfaces. Never invent hex when a token exists.

Modes

ModeFrame

Trade-offs

  • Question the pattern before optimizing execution. Borrowed competitor curves aren't decisions.
  • Motion scope cut where it didn't earn its place (reload/stop animation removed; bookmark animation deferred post-Nova).
  • Spec depth where Eng needs it; exploration where alignment needs it.

Proof

  • Token posture: Smart Window / AI Window, 100% font-size tokenized (AWDTY, Jun 2026).
  • Spec depth: PRD-surface-map across history, thinking states, mode transitions, reduced-motion variants.
  • Program alignment: Product Review 1 and 2 gates before Nightly exposure.

How Smart Window holds the bar

  • Every detail is a decision. If you can't explain why, you didn't design it.
  • Same conviction, every scale. Hover on a settings toggle gets the same care as the thinking state.
  • Design the states nobody sees. Trust lives in error, empty, and off states.
  • Question the pattern, not just the execution. Before making it prettier, ask if the pattern is right.
