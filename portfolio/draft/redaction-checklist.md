# Portfolio redaction checklist

Run before any public deploy, press link, or recruiter send.

## Safe to show publicly

- [ ] Venmo Experience Vision — vision statement, value props, gap matrix structure, workstream process (no internal OKR numbers)
- [ ] Nova Nightly visuals (screenshots you own or Mozilla has published)
- [ ] Public Reddit threads and Mozilla Connect quotes (with attribution)
- [ ] Design principles and mode framing (Private / Classic / AI)
- [ ] AWDTY token propagation percentages (NTP 77.5%, Smart Window 100% font-size)
- [ ] Decision registry **structure** plus up to 3 already-public decisions
- [ ] Operating rules, proof bars, "what we won't count" (from `brief.shareable.md`)
- [ ] PD-OS architecture, critique prep, hub links
- [ ] Podcast / blog posts Mozilla has already published
- [ ] Team size (35-person hybrid org; ~15 product design core OK) and pillar names (Agentic, Habit Loops, Localization) — no individual tier audit

## Show on request only

- [ ] Full decision registry with point-of-contact names
- [ ] Monthly velocity dashboard to leadership
- [ ] Mobile DAU investigation detail and internal metrics
- [ ] Specific Jira board IDs, assignee load, internal ticket links
- [ ] Calibration packets, performance summaries, Lattice content

## Never on portfolio

- [ ] Unreleased PayPal/Venmo metrics, seller data, or confidential OKR targets
- [ ] Individual designer tier audit (A / B / C force-multiplier framing)
- [ ] Calibrated ratings or performance review content
- [ ] "Raja asked me to…" or other named exec 1:1 framing
- [ ] Internal partner criticism with attribution
- [ ] Anything from gitignored `data/people/*/reports/`
- [ ] Full internal `brief.md` (use `brief.shareable.md` language only)
- [ ] `jira.json`, raw metrics snapshots, survey drafts

## Pre-flight (5 minutes)

1. Search site HTML for: `Raja`, `Lattice`, `tier`, `calibrat`, `A/B/C`, internal `@mozilla.com` except your own if listed
2. Confirm all external links resolve (Reddit, Connect, hub, community landing page)
3. Confirm no screenshot shows internal-only UI or unreleased features without clearance
4. Have one Mozilla colleague skim if unsure about a decision row

## Audience-specific notes

| Audience | Emphasize | Hold back |
|----------|-----------|-----------|
| External hire | Nova + operating model + proof strip | Internal velocity sponsor framing |
| Mozilla internal | PD-OS, critique workflow, full decision count | Nothing sensitive — link to Confluence on request |
| Speaking / writing | Community-in-thread, principles | Unverified Nightly promises |
| Advisory | Operating model + PD-OS | Team coaching tiers |
